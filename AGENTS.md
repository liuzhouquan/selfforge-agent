# Engineering notes for future sessions

- Read `docs/development.md` for change entry points, verification gates, and current priorities; distinguish historical audit findings from current open issues in `docs/code-audit.md`.
- This repository is selfForge Agent, a Python Coding Agent. General `code` tasks are the primary workflow; PR Review and Base/Head/Repaired repair remain specialized workflows. Preserve Git history and existing behavior.
- The repository is independent from sibling projects. Study MiniCode, mini-SWE-agent, and OpenHands SDK locally; reuse source only after checking its license and preserving required notices. Do not modify sibling repositories.
- Python 3.11+, uv, FastAPI, Pydantic v2, pytest, Git CLI. Run `uv run pytest` and `uv run ruff check .` before committing. Keep docs truthful about implemented and untested capabilities.
- Before extending Runtime/Harness, fetch main and check open PR dependencies. Prefer integrating validated prerequisites and testing the composition over stacking independent unfinished Runtime variants. Keep original commits and run the complete combined suite; historical per-branch counts are not additive. See `docs/runtime-integration.md`.
- `.github/workflows/ci.yml` runs locked dependencies, Ruff, unit tests, and Docker integration tests on pushes to main and pull requests. Keep its token read-only and do not add model keys. Check the first remote run after changing this workflow; local pytest does not prove the hosted runner works.
- Provider settings use atomic replacement plus a mode-0600 POSIX lock file around the full read-modify-write operation. Keep the lock outside the replaced JSON inode so separate processes serialize updates.
- `runtime.agent.CodingAgent` is the general native tool-calling loop. `runtime.tools.ToolRegistry` validates schemas, paths, timeouts, and output size. Keep tool results in the model conversation and session log. Bound steps and wall time. Do not add `shell=True`.
- Parse JUnit counts and bounded failures together in `verification.junit`. Prioritize diagnostics over noisy stdout and treat them as untrusted test data. Host retests use a fresh bytecode prefix with `-B` to avoid stale imports. Failure snapshots are opt-in, external to evaluated repos, mode-0700/0600 and bounded; keep test text, stacks and private paths out of public benchmark reports/traces. Snapshot write errors must not replace the primary result. Never send holdout diagnostics back to the evaluated Agent.
- `runtime.control` budget notices are regenerated per model request, before the task/history, with context space reserved. Keep them out of durable conversation/compaction history; trace only budget metadata. Guidance cannot add model calls, substitute bash success for run_tests evidence, or promote a step-limited result. Recheck cancellation and deadline after compaction.
- `read_file` permits whole-file reads up to 128 KB or a bounded 200-line range from files up to 2 MB; `search_code` streams matching source up to 2 MB per file and 8 MB in total. Keep path protection and output caps intact when changing these tools.
- `run_tests` and JUnit-backed `TestRunner`/`DockerTestRunner` accept an optional bounded pytest `-k` expression. In benchmark manifests, `agent_test_keyword` must be used by both the Agent instruction and the evaluator's independent visible-test run. Document why a narrowed selection is relevant and disclose broader suite failures.
- DeepSeek thinking-mode replies may include `reasoning_content`; retain it in the mode-0600 session and send it back in later DeepSeek turns, including after resume. Strip that provider-specific field when falling back to other providers. Keep it out of traces, reports, and UI. Context compaction must place synthetic summaries in a system message before the original user task, keep every user message in order, preserve recent interaction turns when budget allows, use syntax- and CJK-aware token estimation, and fail explicitly if non-compactable messages exceed the budget. CodingAgent supports an optional approval_hook callback to intercept and reject actions before execution. Persist the last post-edit test result across resume, persist invalidation before a new user task, any edit attempt, a persistent Host command, or a new test attempt; revoke legacy pending edit/bash/test evidence before appending interruption replies, and require a nonempty final answer before `completed`.
- `OpenAIChatAdapter` gives one model turn a single monotonic deadline across all fallback providers. Pass only the remaining budget to each HTTP attempt, stop before another attempt when the budget expires or the Agent is cancelled, and map those outcomes to `timed_out` or `cancelled`. A currently blocking HTTP request still relies on its transport timeout.
- Web Coding uses this same runtime through `api.coding_jobs.CodingJobManager`. Keep the API localhost-only: reject unknown Host headers and cross-origin browser mutations before routes run. Docker is the default, and host execution requires both `SELFFORGE_ENABLE_HOST_TESTS=1` and per-request trust. Mode-0600 job records, cross-process POSIX workspace locks, and cancellation markers live in the user data directory; active-job limits remain per process. A lost worker is marked interrupted only when its session and workspace can be resumed; resumption is explicit. Preserve older `.workspaces/coding-sessions/` sessions and never run concurrent jobs against one workspace.
- General Coding defaults to a persistent `selfforge/SESSION_ID` branch and worktree from committed HEAD, managed by `runtime.workspace.CodingWorkspaceManager`. Validate the owning repository and branch on resume. Keep worktrees outside source repositories; do not use forced removal for cleanup. Direct source-checkout edits need explicit selection (and Web confirmation). Keep the branch when a clean worktree is removed.
- Workspace listing validates metadata independently. Skip unreadable or mismatched records with a warning that identifies the metadata file; preserve records for manual recovery.
- General command execution defaults to Docker. Host execution needs explicit trust. File tools stay inside the selected workspace. Docker transfers a filtered workspace copy into container tmpfs; do not assume the daemon can resolve WSL bind paths. Bound staging to 8,000 entries, 64 MiB of regular files, a 96 MiB tar archive, and the command deadline; check Web cancellation during staging before launching Docker. Keep the live integration test runnable when a daemon and image are available.
- `run_tests` reuses `TestRunner`/`DockerTestRunner`; `passed` requires exit code 0, positive passed count, and zero failures/errors. All-skipped or empty evidence and invalid/missing JUnit reports must fail closed. Retain the existing Docker executor (image and cancellation marker) with workspace/image validation; unsupported executors cannot fall back to exit-code-only success. New session verification events carry `evidence=junit-workspace-v2` and a validated `workspace_sha256`; older or unbound events require retesting. Keep the Host trust gate and interruption cleanup.
- A general task is `completed` only after nonempty JUnit success with matching pre/post-test workspace fingerprints, a matching current fingerprint and a nonempty final answer; without such evidence use `unverified`. Evaluation must inspect actual files and run pytest independently, not trust the model's answer.
- New sessions and traces are mode-0600 under the user data directory's `selfforge-agent/sessions/`; older sessions in repository `.selfforge/` or app `.workspaces/` remain resumable. `.local/providers.json` may contain a key. Never log or commit keys, generated reports, `.env`, virtual environments, or external course source.
- `ReviewService` findings are heuristic and `suspected`. Existing suite failure alone does not prove a particular finding. Preserve subprocess exit codes and error statuses.
- PR import/review through `gh` never runs code. Web repair requires localhost and defaults to `DockerTestRunner`; host mode requires `SELFFORGE_ENABLE_HOST_TESTS=1` and per-request trust. Preserve JUnit evidence and metadata-only traces.
- Web Coding diff compares the persistent worktree against its base SHA and includes tracked and untracked text. Keep it read-only, bounded, and filter protected paths. Targeted test generation may try up to three distinct pytest candidates within a total time budget, each in temporary Base/Head worktrees; stop at the first Base-pass/Head-assertion-fail result without collection errors. A chosen review risk must match an added line in that diff and remains a hypothesis. `coding.risk_prioritization` scores candidate added-line hypotheses and findings by severity and category profiles; `POST /api/github/prioritize-risks` and CLI `--auto-target` select the top candidate. On differential test results, `coding.causal_investigation` investigates whether Head failure tracebacks link directly to the targeted line/file, reporting high, medium, low, or none confidence. Known models calculate calibrated monetary costs via `runtime.pricing`. Docker is default; host mode requires explicit trust, with the Web operator flag too. Export tests only on explicit request.
- Web Coding diff reads Git patch output with a 96 KiB per-file byte cap before the 24,000-character display cap, and stops an oversized Git process. Bound changed-path enumeration to 256 KiB and fail explicitly when that list is incomplete. Preserve the truncation marker and protected-path filtering.
- Delivery workflows in `runtime.delivery` commit worktree changes and create GitHub pull requests using `gh`. Commits filter protected paths (`.env`, `.venv`, credentials, etc.), require non-empty messages, and default author identity safely in headless environments. PR creation verifies commits exist ahead of base, pushes without `--force`, includes objective test verification status in PR descriptions when available, and fails explicitly on remote or `gh` errors without auto-merging.
- `RepairAgent` keeps three temporary detached worktrees and only emits a patch when Base passes, Head has assertion failure, and Repaired passes. It edits changed Python source, not tests, through the shared `ToolRegistry` with a stricter `EditPolicy`. It shares the Docker executor and session trace, while its model proposer loop remains separate. Integrate it incrementally without weakening evidence or trust gates.
- `eval-suite` is the repeatable general Coding evaluation path. Keep cases pinned to full local Git commit SHAs, holdout tests outside Agent repositories, a failing-assertion baseline check, fresh checkout per repeat, exact allowed change paths, and independent JUnit-backed visible and holdout verification. Run the visible selection on a separate copy before installing the holdout; require a passing nonempty selection and a passing nonempty holdout. Resolve each Docker image reference to an immutable local ID before running cases; host execution needs explicit trust. Freeze manifest bytes at evaluation start so the report hash identifies the loaded cases. Report actual failure categories, latency, and provider-reported tokens without raw provider error bodies, invented model success rates, or prices. The offline demo and three-repository exploratory pilot are separate from product acceptance targets in `docs/product-scope.md`.
- Evaluation reports may include per-run step counts and tool names/success flags for diagnosing limits. Keep model messages, reasoning, tool output, test text, credentials, and private paths out of committed or published reports. Five reference-qualified tasks across three repositories and the separate three-task iterator/traversal run remain below the 20-task acceptance target; the three-task 9/9 result does not add three unique tasks. Keep all historical results separate; do not combine runs with different gates or repeat counts. An `agent_max_steps` attempt remains a failure even if its holdout passes.

- Dependency images are prepared only by explicit `sandbox build`, never by an Agent tool or repository hook. Keep exact hashed wheel pins, bounded context inputs, local base ID resolution, temporary alias cleanup, `--network=none --pull=false`, wheel-only pip install, and `--iidfile` result tracking. Do not copy source, credentials or repository Dockerfiles into this context. Web Coding accepts the prepared image via its `image` field; runtime test isolation and host trust gates remain intact.
- `runtime.environment.detect_repository_environment` safely inspects repository layout (`src` vs flat), dependency and lock files (`pyproject.toml`, `requirements.txt`, `uv.lock`, etc.), test directories, Python version requirements, and hash locks without running arbitrary code or repository hooks.

- General Coding binds its execution environment inside the common Runtime after the Web workspace lock is acquired. Save only mode and immutable local Docker ID in the private session, use that ID for tools, and auto-reuse it when resume omits an image. Fail before model/tools on explicit image/mode mismatches or missing images; never pull/fallback silently. Legacy sessions invalidate test evidence before first environment binding. Web status/history exposes saved mode/ID; Host still requires explicit trust and its dependencies are not pinned. Keep preflight bounded by the task deadline.
- `eval-validate` reuses benchmark preflight and never constructs a model. References stay external and frozen (at most 256 KiB); apply only allowed text patches with Git path checks enabled. Require nonempty visible/holdout passes in separate copies. Invalid references must stop live evaluation before model construction. Legacy manifests without references remain compatible, but do not label them reference-qualified. Keep reference source out of Agent workspaces/conversations and reports; record hashes/counts instead.
- Reference-qualified assets now have a cumulative `benchmark/validated-candidates/suite-five-tasks.json` and a three-case iterator/traversal delta manifest. Keep historical manifests frozen, disclose explicit feature contracts and upstream source evidence, and preserve compatibility controls (directory matches at depth boundaries, ignored-name semantics, lazy iteration and predicate/input exceptions). The zero-chunk case overlaps an earlier pilot; do not add overlapping mechanisms to the unique acceptance count. See `iterator-traversal.md` for actual qualification/model evidence and fixed execution policy.
- Benchmark live visible and holdout verification use separate final-workspace copies created before either selection runs. Preserve that independence for trusted Host runners too; visible tests may write files and must not change the hidden snapshot. `test_benchmark_isolation.py` covers both false success and false failure. Separate copies do not sandbox Host code or defend against malicious absolute-path access.
- `runtime.fingerprint` binds general Coding evidence to root/path/type/mode/content/link-target hashes before/after tests, before reuse and final completion. Preserve descriptor-based no-follow reads, shared Docker exclusions (including pytest/Ruff caches), 8,000-entry/64-MiB/128-depth/10-second limits, task deadline and cancellation checks. Failed/incomplete scans cannot establish evidence. Store only the digest in private v2 events; traces use fixed reasons. This is not an atomic snapshot, workspace lock or Host sandbox; do not promise continuous historical-job revalidation.
