# Engineering notes for future sessions

- This repository is selfForge Agent, a Python Coding Agent. General `code` tasks are the primary workflow; PR Review and Base/Head/Repaired repair remain specialized workflows. Preserve Git history and existing behavior.
- The repository is independent from sibling projects. Study MiniCode, mini-SWE-agent, and OpenHands SDK locally; reuse source only after checking its license and preserving required notices. Do not modify sibling repositories.
- Python 3.11+, uv, FastAPI, Pydantic v2, pytest, Git CLI. Run `uv run pytest` and `uv run ruff check .` before committing. Keep docs truthful about implemented and untested capabilities.
- `runtime.agent.CodingAgent` is the general native tool-calling loop. `runtime.tools.ToolRegistry` validates schemas, paths, timeouts, and output size. Keep tool results in the model conversation and session log. Bound steps and wall time. Do not add `shell=True`.
- DeepSeek thinking-mode replies may include `reasoning_content`; retain it in the mode-0600 session and send it back in later DeepSeek turns, including after resume. Strip that provider-specific field when falling back to other providers. Keep it out of traces, reports, and UI. Context compaction must place synthetic summaries in a system message before the original user task. Persist the last post-edit test result across resume, clear it on a new user task or successful edit, and require a nonempty final answer before `completed`.
- Web Coding uses this same runtime through `api.coding_jobs.CodingJobManager`. Keep the API localhost-only, Docker by default, and host execution behind both `SELFFORGE_ENABLE_HOST_TESTS=1` and per-request trust. Mode-0600 job records, cross-process POSIX workspace locks, and cancellation markers live in the user data directory; active-job limits remain per process. A lost worker is marked interrupted only when its session and workspace can be resumed; resumption is explicit. Preserve older `.workspaces/coding-sessions/` sessions and never run concurrent jobs against one workspace.
- General Coding defaults to a persistent `selfforge/SESSION_ID` branch and worktree from committed HEAD, managed by `runtime.workspace.CodingWorkspaceManager`. Validate the owning repository and branch on resume. Keep worktrees outside source repositories; do not use forced removal for cleanup. Direct source-checkout edits need explicit selection (and Web confirmation). Keep the branch when a clean worktree is removed.
- General command execution defaults to Docker. Host execution needs explicit trust. File tools stay inside the selected workspace. Docker transfers a filtered workspace copy into container tmpfs; do not assume the daemon can resolve WSL bind paths. Keep the live integration test runnable when a daemon and image are available.
- A general task is `completed` only after `run_tests` succeeds after the last edit; without such evidence use `unverified`. Evaluation must inspect actual files and run pytest independently, not trust the model's answer.
- New sessions and traces are mode-0600 under the user data directory's `selfforge-agent/sessions/`; older sessions in repository `.selfforge/` or app `.workspaces/` remain resumable. `.local/providers.json` may contain a key. Never log or commit keys, generated reports, `.env`, virtual environments, or external course source.
- `ReviewService` findings are heuristic and `suspected`. Existing suite failure alone does not prove a particular finding. Preserve subprocess exit codes and error statuses.
- PR import/review through `gh` never runs code. Web repair requires localhost and defaults to `DockerTestRunner`; host mode requires `SELFFORGE_ENABLE_HOST_TESTS=1` and per-request trust. Preserve JUnit evidence and metadata-only traces.
- Web Coding diff compares the persistent worktree against its base SHA and includes tracked and untracked text. Keep it read-only, bounded, and filter protected paths. Targeted test generation may try up to three distinct pytest candidates within a total time budget, each in temporary Base/Head worktrees; stop at the first Base-pass/Head-assertion-fail result without collection errors. A chosen review risk must match an added line in that diff and remains a hypothesis: differential behavior does not prove the finding's cause. Docker is default; host mode requires explicit trust, with the Web operator flag too. Export tests only on explicit request.
- `RepairAgent` keeps three temporary detached worktrees and only emits a patch when Base passes, Head has assertion failure, and Repaired passes. It edits changed Python source, not tests, through the shared `ToolRegistry` with a stricter `EditPolicy`. It shares the Docker executor and session trace, while its model proposer loop remains separate. Integrate it incrementally without weakening evidence or trust gates.
- `eval-suite` is the repeatable general Coding evaluation path. Keep cases pinned to full local Git commit SHAs, holdout tests outside Agent repositories, a failing-assertion baseline check, fresh checkout per repeat, exact allowed change paths, and independent JUnit-backed holdout verification. Resolve each Docker image reference to an immutable local ID before running cases; host execution needs explicit trust. Report actual failure categories, latency, and provider-reported tokens without raw provider error bodies, invented model success rates, or prices. The offline demo and one-case PocketFlow pilot are separate from product acceptance targets in `docs/product-scope.md`.
