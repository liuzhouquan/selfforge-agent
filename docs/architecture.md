# selfForge Agent architecture

## General Coding Runtime

`cli code` resolves a provider (DeepSeek, OpenRouter, or a custom OpenAI-compatible endpoint), creates a `SessionStore` under `${XDG_DATA_HOME:-~/.local/share}/selfforge-agent/sessions/`, selects a command executor, and starts `CodingAgent`. For new tasks, `CodingWorkspaceManager` creates a persistent `selfforge/SESSION_ID` branch and Git worktree from committed HEAD. A resume validates repository ownership and branch before reopening the same worktree. Metadata is mode 0600 under `${XDG_DATA_HOME:-~/.local/share}/selfforge-agent/worktrees/`; the worktree stays there for review and commit. Cleanup uses plain `git worktree remove`, so modified or untracked files block removal, and the branch remains. Explicit `--workspace direct` uses the source checkout instead. Uncommitted source-checkout changes are not copied into a new worktree. CLI sessions formerly stored in a target repository's `.selfforge/` remain discoverable by ID when direct mode is selected.

The local Web API starts the same agent in a bounded background job, exposes status, worktree path, and recent trace events, and can request cancellation. It defaults to worktree mode and requires confirmation for direct source-checkout edits. New Web and CLI sessions share the user data directory, keyed by repository path; earlier Web sessions in ignored `.workspaces/coding-sessions/` remain discoverable by ID. Job status is process-local; an interrupted session can be resumed after restart. Concurrent Web jobs cannot edit the same workspace. Cross-process coordination remains future work.

```text
Task → CodingAgent → ContextManager → OpenAIChatAdapter
                    ↑                  ↓ native tool calls
                 SessionStore ← ToolRegistry → file/search tools
                    ↓                       → DockerExecutor / trusted HostExecutor → pytest
                JSONL trace
```

The loop asks the model for native function calls, validates arguments with Pydantic JSON Schema, executes one tool at a time, and returns every tool result to the model. It stops on a final answer, step/time limit, cancellation, or unrecoverable model failure. Tool errors are returned as tool observations so the model can recover. `completed` requires a successful `run_tests` after the last `edit_file`; otherwise the final state is `unverified`. A model statement alone is never test evidence.

`ToolRegistry` confines paths to the workspace, rejects traversal and symlink escapes, caps file sizes, search results, command timeouts, and tool output. Its `EditPolicy` lets specialized workflows restrict edits to selected files, forbid file creation, and set a smaller size limit. `SessionStore` appends messages and status to mode-0600 JSONL, and a separate metadata-only JSONL trace records model calls, tool durations, token usage, errors, and status transitions. Resume reconstructs messages and fills any interrupted tool response. `ContextManager` estimates tokens by size, truncates tool output, and summarizes earlier actions when a budget is exceeded while retaining the system prompt and original/latest user task. This is a deterministic approximate budget, not tokenizer-exact accounting.

Docker command execution stages a temporary workspace copy that excludes `.env`, `.env.*`, `.local`, `.selfforge`, `.workspaces`, `.git`, `.venv`, and common credential files such as `.npmrc` and `.netrc`. It streams the copy as a tar archive into container tmpfs, so Docker Desktop does not need access to the original WSL filesystem path. Container writes are discarded. It uses `--network none`, a read-only container root, writable size-limited tmpfs, a non-root UID, dropped capabilities, no-new-privileges, CPU/memory/PID limits, and a wall timeout. JUnit XML is read from a separate tmpfs path before the container is removed; stdout alone is never treated as test evidence. The image is built from `docker/Dockerfile`. Host execution requires explicit operator trust, and Web host execution also requires `SELFFORGE_ENABLE_HOST_TESTS=1` and per-request trust. Live Docker integration tests exercise both Web Coding and Base/Head/Repaired verification. `edit_file` writes to the selected worktree directly; Docker isolation applies to commands and tests.

The Coding Web API also exposes a bounded, read-only diff against the worktree's base SHA. It includes committed, uncommitted, and untracked text changes, skips protected paths, and caps the number of files and patch text returned. The diff does not mutate the worktree.

## Existing specialized PR workflows

The FastAPI app serves a PR workbench. `integrations.github_pr` reads PR metadata and patches with `gh api`, creates `PRContext`, and can clone the head into an editable checkout. `ReviewService` runs deterministic baseline findings. `ProviderReviewer` optionally calls configured models and validates findings against actual added lines; findings remain `suspected`. PR import/review never executes PR code.

`RepairAgent` retains its bounded Base/Head/Repaired process in three detached Git worktrees. It only edits changed Python source and emits a patch when Base pytest passes, Head has an assertion failure, and Repaired pytest passes. Its exact replacements now run through the shared `ToolRegistry` with an allowlist of changed source files and a 16 KiB size cap. `DockerTestRunner` uses the shared Docker executor and reads JUnit XML as objective evidence. Host `TestRunner` remains available with explicit trust. CLI and Web repair default to Docker; Web host execution still needs localhost, the operator flag, and per-request trust. A shared `SessionStore` records metadata-only repair status, tool edits, test stages, model attempts, and errors. Repair still has its own proposer loop and does not yet use the general native tool-calling loop.

Provider settings and HTTP transport are shared across general coding and PR workflows. Keys stay in the server environment or ignored `.local/providers.json`; traces do not include credentials. CLI evaluation uses generated fixtures and independently reruns tests to prevent model self-assessment from determining success.

`runtime.benchmark` adds a separate repeated-evaluation path for the general Coding Agent. A versioned manifest names local Git repositories, full commit SHAs, exact allowed change paths, visible test paths, and pytest holdouts stored outside those repositories. The evaluator freezes and hashes each holdout, checks that it fails by assertion on the pinned baseline, then starts every repeat in a fresh temporary checkout. The Agent sees the repository and visible tests, while the evaluator copies the final checkout and inserts the unseen holdout only for independent verification. Success requires an Agent `completed` state, permitted source changes, and a JUnit-backed holdout pass with at least one test. Docker is the default; trusted host execution is explicit. The report includes per-case results, failure categories, duration, provider-reported token counts, commit SHAs, holdout hashes, and the local Docker image ID. It contains no raw model or test output. This is an evaluation harness, not a claim of real-repository success until a diverse live task set is run. See [benchmark.md](./benchmark.md).

`DifferentialTestGenerator` uses the shared OpenAI-compatible native tool-calling adapter to request a pytest candidate. Its `run_many` loop tries at most three, feeds prior outcomes into the next prompt, rejects AST-identical duplicates without rerunning tests, stops at the first differential result, and enforces a total time budget. Each candidate gets temporary detached Base and Head worktrees, writes the same test to both, and runs only that file through `DockerTestRunner` by default (or explicit trusted host `TestRunner`). JUnit counts determine whether Base passed and Head failed an assertion without collection errors. Any other result remains inconclusive or an error. A selected review risk is checked against an actual added diff line before prompting; its description remains a hypothesis. Source checkouts stay untouched; the selected test is exported only on explicit CLI output or browser download. Both Web endpoints are localhost-only, and host mode requires the operator flag plus per-request trust. Metadata-only traces live in the user data directory. This flow measures candidate test behavior, not the causal link to a particular PR finding. Automatic risk selection remains future work.
