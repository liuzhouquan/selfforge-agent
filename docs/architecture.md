# selfForge Agent architecture

## General Coding Runtime

`cli code` resolves a provider (DeepSeek, OpenRouter, or a custom OpenAI-compatible endpoint), creates a `SessionStore` under `${XDG_DATA_HOME:-~/.local/share}/selfforge-agent/sessions/`, selects a command executor, and starts `CodingAgent`. For new tasks, `CodingWorkspaceManager` creates a persistent `selfforge/SESSION_ID` branch and Git worktree from committed HEAD. A resume validates repository ownership and branch before reopening the same worktree. Metadata is mode 0600 under `${XDG_DATA_HOME:-~/.local/share}/selfforge-agent/worktrees/`; listing validates each record independently and warns with the metadata path when it skips a malformed or mismatched entry. The worktree stays there for review and commit. Cleanup uses plain `git worktree remove`, so modified or untracked files block removal, and the branch remains. Explicit `--workspace direct` uses the source checkout instead. Uncommitted source-checkout changes are not copied into a new worktree. CLI sessions formerly stored in a target repository's `.selfforge/` remain discoverable by ID when direct mode is selected.

The local Web API starts the same agent in a bounded background thread, exposes status, worktree path, and recent trace events, and can request cancellation. It defaults to worktree mode and requires confirmation for direct source-checkout edits. New Web and CLI sessions share the user data directory, keyed by repository path; earlier Web sessions in ignored `.workspaces/coding-sessions/` remain discoverable by ID. `CodingJobManager` atomically stores mode-0600 job records in `selfforge-agent/jobs/`, so another process can query recent jobs for a repository. A POSIX file lock keyed by resolved workspace path is held through execution and also guards worktree removal. A file marker carries cancellation requests across processes; the Agent checks it between calls. After a server exits, an active record with no lock becomes `interrupted` if its session and workspace still exist; the user explicitly starts a new job to resume that session. A job that ended before saving its session is marked failed. The active-job count is per process, and running calls are not automatically restarted.

```text
Task → CodingAgent → ContextManager → OpenAIChatAdapter
                    ↑                  ↓ native tool calls
                 SessionStore ← ToolRegistry → file/search tools
                    ↓                       → DockerExecutor / trusted HostExecutor → pytest
                JSONL trace
```

The loop asks the model for native function calls, validates arguments with Pydantic JSON Schema, executes one tool at a time, and returns every tool result to the model. It stops on a final answer, step/time limit, cancellation, or unrecoverable model failure. Tool errors are returned as tool observations so the model can recover. `completed` requires a successful `run_tests` after the last potentially persistent write and a nonempty final answer; otherwise the final state is `unverified` or `failed`. An `edit_file` attempt or trusted Host `bash` command invalidates earlier test evidence even if it fails, because either may leave partial edits. Docker `bash` works on a discarded copy and preserves that evidence. Invalidation is appended to the session before an edit, persistent command, or new test attempt starts, and before a new user task is saved; if that append fails, the write is not executed. A later failed or interrupted test clears earlier success evidence. Resume conservatively revokes evidence for legacy pending edit/bash/test calls before adding interruption replies (including bash when its former executor is unknown). Read-only pending calls preserve evidence. These rules cover process interruption, not power-loss atomicity or external edits. On the last available model turn, successful test evidence causes the Agent to omit tool schemas and request a final answer; if a provider still returns tool calls, those calls are not run and the result remains `max_steps`. A model statement alone is never test evidence. General `run_tests` currently uses the pytest exit status without JUnit counts, so an all-skipped suite can still yield `completed`; this known gap is tracked as P1-08 in `docs/code-audit.md`. Independent evaluation retains its stricter nonempty-pass gate.

Each model turn has one monotonic deadline across provider fallback. The adapter passes only the remaining time to the next HTTP attempt and checks cancellation before another provider starts. Exhausted budget and cancellation become `timed_out` and `cancelled` Agent statuses. An in-flight HTTP attempt is bounded by the transport timeout; cancellation is observed when that attempt returns.

`ToolRegistry` confines paths to the workspace, rejects traversal and symlink escapes, caps file sizes, search results, command timeouts, and tool output. Whole-file `read_file` calls are limited to 128 KB; line-range reads can select up to 200 lines from a file up to 2 MB. `search_code` streams eligible files up to 2 MB each, with an 8 MB total scan cap. Its `EditPolicy` lets specialized workflows restrict edits to selected files, forbid file creation, and set a smaller size limit. `SessionStore` appends messages, test verification state, and status to mode-0600 JSONL, and a separate metadata-only JSONL trace records model calls, tool durations, token usage, errors, and status transitions. Resume reconstructs messages, the latest test state, and any interrupted tool response. A fresh user task clears prior test evidence. DeepSeek thinking-mode assistant messages retain `reasoning_content` in the private session for the next request, as required by the [DeepSeek tool-calling protocol](https://api-docs.deepseek.com/guides/thinking_mode/); other providers receive messages without that field. Traces and benchmark reports do not include model reasoning. `ContextManager` estimates tokens by size, truncates tool output, and summarizes earlier actions into a system message before the original task when a budget is exceeded, retaining the system prompt and every user message in order. If those messages cannot fit, compaction fails explicitly. This is a deterministic approximate budget, not tokenizer-exact accounting.

`run_tests` now delegates to the existing `TestRunner` or `DockerTestRunner`, rather than inferring success from command stdout. All runner callers require exit code 0, at least one passing test, and no failures/errors for `status=passed`; all-skipped/empty evidence and missing, malformed, negative or inconsistent JUnit counts are rejected. The Docker runner reuses the supplied executor only when its workspace and image match, retaining the Web job cancellation marker. Host tests use the Agent process Python interpreter after explicit `HostExecutor` trust. Private verification events carry `evidence=junit-v1`; old exit-code-only events remain readable but cannot restore success without retesting. Historical job records are not rewritten. See [test evidence](./test-evidence.md).

`run_tests` and the JUnit-backed test runners accept an optional bounded pytest `-k` expression. In `eval-suite`, the evaluator independently runs the manifest's visible test path and keyword selection on a copy of the Agent workspace, then installs and runs the unseen holdout separately. Both runs must contain passing tests and have no failures or collection errors. The report records their statuses and counts independently; a green unrelated Agent test cannot replace the specified visible selection.

Docker command execution stages a temporary workspace copy that excludes `.env`, `.env.*`, `.local`, `.selfforge`, `.workspaces`, `.git`, `.venv`, and common credential files such as `.npmrc` and `.netrc`. Staging stops at 8,000 entries, 64 MiB of regular-file content, or a 96 MiB tar archive; it checks the command deadline and Web cancellation while copying and packing. Exceeding a limit returns an error before launching a container, and the temporary copy is removed. The archive is streamed into container tmpfs, so Docker Desktop does not need access to the original WSL filesystem path. Container writes are discarded. It uses `--network none`, a read-only container root, writable size-limited tmpfs, a non-root UID, dropped capabilities, no-new-privileges, CPU/memory/PID limits, and a wall timeout. JUnit XML is read from a separate tmpfs path before the container is removed; stdout alone is never treated as test evidence. The image is built from `docker/Dockerfile`. Host execution requires explicit operator trust, and Web host execution also requires `SELFFORGE_ENABLE_HOST_TESTS=1` and per-request trust. Live Docker integration tests exercise both Web Coding and Base/Head/Repaired verification. `edit_file` writes to the selected worktree directly; Docker isolation applies to commands and tests.

The Coding Web API also exposes a bounded, read-only diff against the worktree's base SHA. It includes committed, uncommitted, and untracked text changes and skips protected paths. Git patch output is read incrementally up to 96 KiB per file before the 24,000-character display cap; an oversized Git process is stopped and the response carries a truncation marker. Changed-path enumeration is capped at 256 KiB and fails explicitly if incomplete. The response includes at most 40 files. The diff does not mutate the worktree.

The shared runners parse counts and bounded failure records in
`verification.junit`; `verification.feedback` prioritizes labels/messages over
process output for the existing native tool loop. Optional
`runtime.failure_artifacts` snapshots retain independent diagnostics in private
local files without sending holdout data to the Agent or adding test text to
reports. Host pytest uses a fresh bytecode-cache namespace so rapid same-size
edits cannot reuse stale source imports. See [test-diagnostics.md](./test-diagnostics.md).

## Existing specialized PR workflows

The FastAPI app serves a PR workbench. `integrations.github_pr` reads PR metadata and patches with `gh api`, creates `PRContext`, and can clone the head into an editable checkout. `ReviewService` runs deterministic baseline findings. `ProviderReviewer` optionally calls configured models and validates findings against actual added lines; findings remain `suspected`. PR import/review never executes PR code.

`RepairAgent` retains its bounded Base/Head/Repaired process in three detached Git worktrees. It only edits changed Python source and emits a patch when Base pytest passes, Head has an assertion failure, and Repaired pytest passes. Its exact replacements now run through the shared `ToolRegistry` with an allowlist of changed source files and a 16 KiB size cap. `DockerTestRunner` uses the shared Docker executor and reads JUnit XML as objective evidence. Host `TestRunner` remains available with explicit trust. CLI and Web repair default to Docker; Web host execution still needs localhost, the operator flag, and per-request trust. A shared `SessionStore` records metadata-only repair status, tool edits, test stages, model attempts, and errors. Repair still has its own proposer loop and does not yet use the general native tool-calling loop.

Provider settings and HTTP transport are shared across general coding and PR workflows. Keys stay in the server environment or ignored `.local/providers.json`; updates serialize the complete read-modify-write with a mode-0600 POSIX lock file and replace the JSON atomically. Traces do not include credentials. CLI evaluation uses generated fixtures and independently reruns tests to prevent model self-assessment from determining success.

`runtime.benchmark` adds a separate repeated-evaluation path for the general Coding Agent. A versioned manifest names local Git repositories, full commit SHAs, exact allowed change paths, visible test paths, external pytest holdouts, and optional per-case Docker images. The evaluator freezes and hashes each holdout, checks that it fails by assertion on the pinned baseline, resolves image tags to immutable local IDs, then starts every repeat in a fresh temporary checkout. The Agent sees the repository and visible tests, while the evaluator copies the final checkout and inserts the unseen holdout only for independent verification. Success requires an Agent `completed` state, at least one file change with every changed path permitted, an independent pass of the selected visible tests with at least one passing test, and a separate JUnit-backed holdout pass with at least one passing test. Failures, collection errors, timeouts, missing or empty selections, and test-environment errors prevent success and are reported by category. Docker is the default; trusted host execution is explicit. The report includes per-case results, sanitized Agent error codes, duration, provider-reported token counts, commit SHAs, holdout hashes, and case-to-image ID mappings. It contains no raw model or test output. This is an evaluation harness, not a claim of broad real-repository success until a diverse live task set is run. See [benchmark.md](./benchmark.md).

`DifferentialTestGenerator` uses the shared OpenAI-compatible native tool-calling adapter to request a pytest candidate. Its `run_many` loop tries at most three, feeds prior outcomes into the next prompt, rejects AST-identical duplicates without rerunning tests, stops at the first differential result, and enforces a total time budget. Each candidate gets temporary detached Base and Head worktrees, writes the same test to both, and runs only that file through `DockerTestRunner` by default (or explicit trusted host `TestRunner`). JUnit counts determine whether Base passed and Head failed an assertion without collection errors. Any other result remains inconclusive or an error. A selected review risk is checked against an actual added diff line before prompting; its description remains a hypothesis. Source checkouts stay untouched; the selected test is exported only on explicit CLI output or browser download. Both Web endpoints are localhost-only, and host mode requires the operator flag plus per-request trust. Metadata-only traces live in the user data directory. This flow measures candidate test behavior, not the causal link to a particular PR finding. Automatic risk selection remains future work.
