# selfForge Agent 产品边界与验收

## 目标

selfForge Agent 面向 Python Git 仓库：用户从 Web 工作台或 CLI 提交自然语言开发任务，单个 Agent 在独立 worktree 中调用受限工具修改代码，在隔离环境运行测试，并交付 Diff、执行轨迹、测试证据与失败原因。会话可恢复，工作区可检查和清理。PR 导入、审查、差异测试和修复是专项工作流。

当前不以多 Agent、通用 MCP 平台、额外 RAG、跨语言 IDE 或大型前端为目标。`completed` 表示 Agent 取得非空 JUnit 成功、测试前后与当前工作区指纹一致，并给出非空最终答复；它不等于任务需求已经得到充分验证。

## 完成条件

| 范围 | 可检查的验收条件 | 当前状态 |
| --- | --- | --- |
| Coding Runtime | 真实模型自主读、改、测；错误可回填；步数/时间上限；文件修改留在独立工作区 | 基础实现；真实仓库稳定性待评测 |
| Testing Harness | Docker 默认隔离；项目依赖可复现；独立测试证据与失败分类；生成的测试经过 Base/Head 验证 | 通用 Coding/Repair 共用非空 JUnit 门槛；Docker、差异验证、显式离线依赖镜像和会话环境绑定已实现；已能只读识别布局/依赖文件；自动安装环境和真实项目修复稳定性待加强 |
| 任务可靠性 | Web 任务重启后可查询/续跑；跨进程不会并发修改同一工作区；取消状态明确 | 持久任务记录、显式续跑、跨进程文件锁与取消标记已实现；任务不会自动续跑，活动数量限制仍按进程计算 |
| 客观评测 | 至少 3 个真实 Python 仓库、20 个固定 SHA 任务、每题至少 3 次真实模型运行；独立可见与隐藏测试，公开成功率、失败原因、耗时与 token 用量 | 重复评测工具、锁定镜像、独立可见测试及外部参考预检已有；5 道任务跨 3 仓库通过参考预检，其中另选三题各 3 次 DeepSeek 得到 9/9。早期结果另记，不能相加；正式 20 题 × 3 次验收仍未完成，见[评测记录](./evaluation.md) |
| 交付与回归 | Web/CLI 可审查 Diff 与测试证据；显式提交并创建/恢复 PR；CI 持续运行静态检查、单元测试和 Docker 集成测试 | 交付入口、保护路径、固定提交证据和重试恢复已有；[PR #34](https://github.com/liuzhouquan/selfforge-agent/pull/34) 记录实际 Git/gh 后端创建与重复调用验证，CLI/Web 有回归；不自动强推或合并。当前检查见对应提交的 CI |

这里的数量是项目验收目标，不是已有成绩。只有真实任务集完成并公开运行条件后，才根据首轮基线确定合理的模型成功率门槛；演示夹具不得混入正式结果。

## 近期顺序

1. 扩展并冻结至少 3 个真实仓库、20 个互不重复且有行为契约/参考修复的任务；固定供应商策略后每题运行至少 3 次，报告失败分布。
2. 按[可接手任务](./backlog.md)分成小型工作单元；已复现的可靠性问题优先处理，再推进正式评测。已有交付、只读环境发现和 Web 恢复能力不重复实现。过程与验收命令见[开发指南](./development.md)，长期能力方向见[路线图](./roadmap.md)。
