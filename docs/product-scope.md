# selfForge Agent 产品边界与验收

## 目标

selfForge Agent 面向 Python Git 仓库：用户从 Web 工作台或 CLI 提交自然语言开发任务，单个 Agent 在独立 worktree 中调用受限工具修改代码，在隔离环境运行测试，并交付 Diff、执行轨迹、测试证据与失败原因。会话可恢复，工作区可检查和清理。PR 导入、审查、差异测试和修复是专项工作流。

当前不以多 Agent、通用 MCP 平台、跨语言 IDE 或大型前端为目标。`completed` 仅表示最后一次编辑后 Agent 运行的 pytest 成功；它不等于任务需求已经得到充分验证。

## 完成条件

| 范围 | 可检查的验收条件 | 当前状态 |
| --- | --- | --- |
| Coding Runtime | 真实模型自主读、改、测；错误可回填；步数/时间上限；文件修改留在独立工作区 | 基础实现；真实仓库稳定性待评测 |
| Testing Harness | Docker 默认隔离；项目依赖可复现；独立测试证据与失败分类；生成的测试经过 Base/Head 验证 | pytest、Docker、差异验证及显式离线依赖镜像已实现（ItsDangerous 297 项通过）；自动环境识别和通用任务测试闭环待加强 |
| 任务可靠性 | Web 任务重启后可查询/续跑；跨进程不会并发修改同一工作区；取消状态明确 | 持久任务记录、显式续跑、跨进程文件锁与取消标记已实现；任务不会自动续跑，活动数量限制仍按进程计算 |
| 客观评测 | 至少 3 个真实 Python 仓库、20 个固定 SHA 任务、每题至少 3 次真实模型运行；独立可见与隐藏测试，公开成功率、失败原因、耗时与 token 用量 | 重复评测工具、按案例锁定镜像及独立可见测试门槛已实现；3 仓库/4 道项目自编任务在新门槛下各运行 1 次得到 4/4。旧门槛的 3 题各重复 3 次得到 8/9；正式 20 任务集尚未建立 |
| 交付与回归 | Web/CLI 可审查 Diff 与测试证据；CI 持续运行静态检查、单元测试和可用时的 Docker 集成测试 | Diff 与本地检查已有；GitHub Actions 首次远端运行已通过 Ruff、90 项单元测试和 5 项 Docker 集成测试；完整 PR 提交流程待补 |

这里的数量是项目验收目标，不是已有成绩。只有真实任务集完成并公开运行条件后，才根据首轮基线确定合理的模型成功率门槛；演示夹具不得混入正式结果。

## 近期顺序

1. 将[重复评测工具](./benchmark.md)的真实 Python 仓库任务集扩至 20 题，事先固定任务、隐藏测试与执行策略，再记录首轮失败分布。
2. 针对评测发现的问题，优先补项目依赖环境、测试选择与修复闭环。
3. 完成 CI 与交付流程，并继续验证 Web 任务在真实服务部署下的恢复行为。
